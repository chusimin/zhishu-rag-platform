# 知枢 · 前端原型 v0.1

对标 FastGPT / Dify 的可交互原型，用于评审信息架构与核心交互，确认后再迁移到正式前端 `../src`。

> **所有业务数据、报告内容、统计数字都是虚构的演示数据**，原型不连接后端。

## 打开方式

- **直接双击** `知枢-前端原型.html`（单文件，离线可用，Chrome / Edge / Safari）
- 或开发模式：`pnpm install && pnpm dev`，然后打开 <http://127.0.0.1:4180>
- 重新生成单文件：`pnpm build`

左侧导航底部的 **「开发标注」** 开关会在每个功能旁显示后端就绪度：

| 标注 | 含义 |
|---|---|
| `后端已有` | 现有 FastAPI 后端已实现，前端接上即可 |
| `后端部分` | 有基础实现，需要扩展 |
| `需新开发` | 后端尚无对应能力 |

## 信息架构

```
工作台   业务人员入口：按场景找应用、收藏、最近使用、本月业务沉淀
应用     简易应用 / Chat Flow / Agent 的搭建、调试、发布、日志、评测、版本
知识库   数据集、导入向导（9 种切块 + 实时预览）、分块管理、检索测试、配置
工具     工具库（HTTP）、MCP 服务、工作流插件、模型
看板     调用量、满意度、命中率、转人工率、知识缺口回流
可观测   知识构建、Agent Trace、对话日志、Token 与费用归因
评测集   线上 Good / Bad Case 回流、人工汇总、标准补齐与回归评测
设置     成员、角色权限、Agent 接入 Token、审计日志
```

原来 9 个入口（交付工作台 / AI 设计室 / 应用中心 / 业务应用 / 在线对话…）收敛成 5 个，「设计室」并入应用编排，「业务应用 + 在线对话」并入工作台。

## 推荐评审路径

| # | 路径 | 看什么 |
|---|---|---|
| 1 | 工作台 | 业务人员视角：按 5 类场景找应用 |
| 2 | 知识库 → 产品手册与 FAQ → 导入数据 → 下一步 | **切块**：每个文件单独选方式，按文件类型推荐，调参数右侧实时预览；切到「父子分块」「自定义分隔符 →「第X条」」「问答对拆分」「表格按行」对比效果 |
| 3 | 知识库 → 检索测试 | 切换语义 / 全文 / 混合检索，看编号类问题（E07）的召回差异 |
| 4 | 知识库 → 数据集 → 点 ES-200 手册 → 点一个分块 | 一块多索引（自定义问法、AI 生成问题） |
| 5 | 应用 → 行业研究报告撰写 → 运行调试 → 运行 | **Chat Flow**：节点逐级执行、并行分支、表单 / 用户选择节点暂停等待交互 |
| 6 | 应用 → 合同风险审校 | 问题分类 + 判断器的多分支，未命中分支自动置灰 |
| 7 | 应用 → 智能客服助手 | **Agent**：工具、知识库即工具、转人工、记忆；右侧调试可展开每轮规划与工具调用 |
| 8 | 工作台 → 行业研究报告撰写 | 业务端完整流程：表单 → 大纲确认 → 分章撰写 → Word 成稿 |
| 9 | 工作台 → 合同风险审校 | 上传 → 风险清单（高 / 中 / 低 + 原文 + 依据 + 修改建议） |
| 10 | 应用 → 任一应用 → 发布 | 评测门禁（沿用现有后端的 Pass/Fail 规则）、版本回滚、多渠道发布 |
| 11 | 看板 | 知识缺口 → 一键补充知识，形成业务沉淀闭环 |
| 12 | 可观测 → 总览 | 从异常卡片下钻到 Agent Trace 或知识构建任务 |
| 13 | 可观测 → Agent 运行 | 查看单次输入输出、上下文、工具、Skill、Token、费用与 Harness 异常 |
| 14 | 可观测 → 用量与费用 | 对比应用 / 模型归因，查看预算与计价口径 |
| 15 | 可观测 → 对话日志 | 勾选线上会话，标记 Good / Bad Case 并回流到评测集 |
| 16 | 评测集 | 汇总 Case、补充期望输出与判定规则、移动到其他评测集 |

可观测模块的对象模型、状态口径与完整验收路径见 [`OBSERVABILITY_DESIGN.md`](OBSERVABILITY_DESIGN.md)。

## 切块方式

| 方式 | 适用 | 后端 |
|---|---|---|
| 智能分块 | 大多数文档（默认） | 已有（递归切分） |
| 按标题层级 | 手册、制度、规范 | 需新开发 |
| 自定义分隔符（支持正则） | 条款、清单 | 部分（分隔符写死） |
| 固定长度 | 转写稿、无结构长文本 | 已有 |
| 父子分块 | 长篇研报、技术文档 | 已有 |
| 语义分块（LLM） | 主题跳跃的长文 | 已有（含逐字校验） |
| 问答对拆分（LLM） | FAQ、客服、培训材料 | 需新开发 |
| 按页切分 | PPT、扫描件 | 需新开发 |
| 表格按行（表头作上下文） | 参数表、价格表 | 部分 |

另有处理增强：问题索引、摘要索引、元数据抽取（已有）、图片理解 / OCR（已有）、去页眉页脚。

## 支撑原型所需的后端工作

详见 [`../docs/AUDIT.md`](../docs/AUDIT.md) 第 3 节，优先级：

1. **Manifest v2 + 图执行器**：`type: simple | chatflow | agent`，节点 / 连线 / 变量池 / 交互节点暂停恢复，复用 `TraceStep` 记录每个节点
2. **Agent 循环**：tool calling + 工具注册表（HTTP / 知识库 / 子工作流 / MCP / 转人工）
3. **切块配置下沉到文件 + `chunk-preview` 接口**，补齐标题层级、问答对、按页、正则分隔符
4. **混合检索**：tsvector + 中文分词 + RRF
5. **SSE 流式**覆盖全部应用类型
6. 一块多索引、知识缺口聚类、渠道接入（嵌入 / 企业微信 / 飞书）

## 代码结构

```
src/
  data/mock.ts          全部演示数据（场景、应用、知识库、分块、工具、日志）
  lib/chunker.ts        浏览器端切块预览（9 种策略的真实实现，便于对照后端）
  lib/mockChat.ts       脚本化对话：工具调用、引用、转人工
  flow/defs.tsx         20 种工作流节点定义与节点组件
  flow/graphs.ts        报告撰写 / 合同审校 / 项目周报 三个示例流程
  editors/              简易应用、Chat Flow 画布、Agent 三种编排器
  pages/                各页面
```

技术栈：React 18 + TypeScript + Vite + React Router（Hash）+ `@xyflow/react` + lucide-react。迁移到正式前端时，画布、切块预览和对话面板可以直接复用。
