# 知枢可观测模块 · 原型功能设计

## 1. 目标与边界

可观测模块服务平台管理员、应用交付工程师和知识库运营人员，解决三个问题：

1. 系统现在是否健康，异常集中在哪里。
2. 某次回答、Agent 运行或知识构建为什么失败、慢或昂贵。
3. 哪个应用、模型、工具、Skill 或知识库正在制造质量与成本问题。

原型只展示交互和信息结构，所有数据都是虚构演示数据。费用是按调用时价格快照计算的估算值，不等同于供应商最终账单。

## 2. 统一对象模型

| 层级 | 对象 | 主标识 | 用途 |
|---|---|---|---|
| 业务会话 | Conversation | `conversation_id` | 聚合同一用户的多轮对话、反馈和渠道 |
| 单次执行 | Trace / Run | `trace_id` | 记录一次用户输入到最终输出的完整调用链 |
| 执行步骤 | Span | `span_id` | 模型、检索、工具、Skill、工作流节点和 Harness 的单步状态 |
| 知识任务 | Build job | `build_id` | 记录文件解析、OCR、元数据、分块、Embedding、索引全过程 |
| 费用明细 | Usage record | `usage_id` | 按 Trace、模型、应用、租户和计价快照归集 Token 与费用 |

Conversation 与 Trace 是一对多；Trace 与 Span、Usage record 是一对多。知识构建使用独立 Build job，但可从失败步骤跳到对应任务详情。

## 3. 信息架构

新增一级入口「可观测」，包含五个视图：

- **总览**：成功率、P95 延迟、异常数、费用和高风险异常；从指标直接下钻到运行。
- **知识构建**：文件级构建任务、阶段状态、吞吐、失败原因和重试入口。
- **Agent 运行**：单次输入输出、运行状态、上下文、模型/工具/Skill 调用、Token、费用和 Harness 异常。
- **对话日志**：会话级多轮记录、用户反馈、渠道、版本、引用和会话总消耗。
- **用量与费用**：按应用、模型、提供商聚合输入/输出/缓存 Token、费用、预算和趋势。

## 4. 核心交互

### 4.1 总览

- 时间范围、应用、环境筛选对全部指标生效。
- 异常卡片区分失败、告警与预算风险，点击进入对应对象。
- 最近 Trace 表提供统一排障入口。

### 4.2 知识构建

- 任务列表展示知识库、文件、触发方式、总体状态、当前阶段、耗时和分块数。
- 详情抽屉按时间线展示上传、解析、OCR、元数据、分块、Embedding、索引阶段。
- 每一阶段展示输入输出数量、耗时和错误；失败阶段展示可执行的恢复建议。
- 原型仅展示“重试失败步骤”按钮，不执行真实任务。

### 4.3 Agent 运行与 Trace 详情

- 列表展示单次输入摘要、应用、状态、总耗时、工具/Skill 状态、Token、费用和时间。
- 详情固定包含：
  - 以一条连续执行轨迹展示用户输入、上下文装配、显式 Plan、ReAct 的 Action / Observation、Harness 事件与最终输出；不把这些信息拆散到不同标签页；
  - 运行元信息：应用/版本、用户、会话、渠道、模型、环境；
  - 调用上下文：System Prompt、对话历史、检索内容、工具结果、上下文占用与截断；
  - Span 时间线：规划、模型、知识检索、工具、Skill、校验/护栏和重试；每个节点可展开请求、响应、执行载荷或代码快照，并提供逐段解释；
  - 每步状态、耗时、输入/输出 Token、费用、请求与响应摘要；
  - Harness 异常：上下文截断、循环上限、工具参数校验、超时重试、Skill 加载失败、预算/权限/沙箱拦截。
- 敏感字段默认脱敏，查看原文需要权限并进入审计日志。
- “完整 Plan”指 Agent 实际显式输出并写入 Trace 的计划、动作和观察结果；模型不可见的隐式推理不存在可读取日志，界面不得用生成内容伪装。

### 4.4 对话日志

- 会话列表与单次 Trace 分开，避免把“4 轮对话”误当成“一次模型调用”。
- 会话详情展示多轮消息、每轮对应 Trace、引用、反馈和累计成本。
- 可从任意一轮进入 Trace 详情，也可把差评加入评测集。

### 4.5 用量与费用

- 同时展示 Token 数和费用，输入、输出、缓存命中分开统计。
- 提供应用、模型、提供商三个归因维度，并保留 Trace 级明细下钻。
- 预算展示已用比例、预测月底消耗和告警阈值。
- 每条费用记录绑定模型价格版本、币种和计价时间，供应商账单同步状态单独显示。

## 5. 状态与权限

- 状态统一为：排队中、运行中、成功、部分成功、失败、已取消、超时。
- “部分成功”用于主流程完成但有工具、Skill 或异步写回失败的情况。
- 只读观察与操作权限分离：查看日志不等于允许重试、终止、导出原文或修改预算。
- 输入输出、Prompt、工具参数和检索内容按租户设置保留期；删除后只保留聚合指标。

## 6. 原型验收路径

1. 可观测 → 总览 → 点击异常 Agent Trace，查看完整单次输入输出与 Harness 告警。
2. 可观测 → 知识构建 → 打开失败任务，定位到 Embedding 阶段并看到恢复建议。
3. 可观测 → Agent 运行 → 筛选异常运行，确认工具、Skill、Token、上下文均可查看。
4. 可观测 → 对话日志 → 打开多轮会话，再下钻到某一轮 Trace。
5. 可观测 → 用量与费用 → 查看应用与模型归因、预算风险和费用口径。
6. 可观测 → 对话日志 → 批量选择真实会话，标记 Good / Bad Case 并回流到独立评测集。
7. 评测集 → 打开待补标准的 Bad Case，补齐期望输出或判定规则后变为可运行状态。

## 7. 线上 Case 回流

- 回流在单个评测集内以 Trace 为去重键；同一 Trace 可加入不同评测集，并保留输入、线上实际输出、会话、应用版本、模型、渠道和发生时间。
- Trace 详情和会话详情均提供单条 Good / Bad Case 保存入口；列表批量回流用于每天集中整理。
- Good Case 表示线上结果已被人工确认，可将当前输出作为参考答案或补充保持项。
- Bad Case 表示线上结果存在问题；未填写期望输出或判定规则时进入“待补标准”，不得直接参与自动评测。
- 评测集是独立模块，支持按业务场景汇总、批量移动、标签筛选和人工复核，不与日志保留期绑定。
